# Pidlok Hub

เว็บหน้าร้านสำหรับธุรกิจ เน้นมือถือที่ `pidlokhub.com/businessname` รวมข้อมูลร้าน Social, Map, Delivery และสินค้าในหน้าเดียว พร้อม CMS จัดหน้าแบบโมดูล

## ทิศทางล่าสุด

- หน้าร้านแนว Social profile: เข้าใจเร็ว รูปเด่น ปุ่มกดง่าย
- Section เป็นโมดูล เลือก Layout ลากเรียง เปิด–ปิด และสร้าง DIY Section ได้
- เปลี่ยนธีม สีพื้น และรูปทรง Avatar โดยคงข้อมูลเดิม
- รองรับการต่อยอด Google SSO แพ็กเกจสมาชิก หน้าแยก และ Add-on เช่น จองคิวหรือนัดหมายในเฟสถัดไป

Repository นี้เริ่มต้นด้วยเอกสารและภาพแนวทางออกแบบ ยังไม่มีแอปที่พัฒนาเสร็จ ภาพร้าน อาหาร และราคาในภาพเป็นตัวอย่าง ต้องยืนยันก่อนใช้งานจริง


## ต้นแบบ HTML ในเครื่อง

เปิด [บ้านก๋ง-prototype.html](บ้านก๋ง-prototype.html) ด้วย Chrome, Safari หรือ Edge ได้โดยตรง ไฟล์นี้รวมรูปและส่วนประกอบทั้งหมดไว้แล้ว ไม่ต้องติดตั้งหรือเข้าสู่ระบบ

- สลับระหว่าง **หน้าร้าน** และ **จัดการร้าน** ด้วยปุ่มด้านบน
- แท็บ **Section**: กดหัวการ์ดเพื่อพับ–เปิดรายละเอียด แยกจากสวิตช์แสดง/ซ่อนบนหน้าร้าน ภายในมีการ์ด Layout และปุ่มขึ้น–ลง/ลบ ลากไอคอนจุดเพื่อเรียง หรือเพิ่มโมดูลและสร้าง DIY Section
- แท็บ **ธีมแสดงผล**: Social / Minimal / Warm สีพื้นสำเร็จรูปหรือรหัสสี ขนาดและรูปแบบฟอนต์ และรูปทรง Avatar
- แท็บ **โปรไฟล์**: แก้ข้อมูลร้าน อัปโหลดภาพ Avatar ปรับตำแหน่งและซูมรูป
- เมนูสินค้าเลือกกริด / รายการ / สไลด์ได้ และเลือกจำนวนคอลัมน์ในแบบกริด
- แตะสินค้าเพื่อดูรายละเอียด รูปสไลด์ และปุ่มแชร์
- **เผยแพร่** ในต้นแบบนี้สร้างสำเนาฉบับเผยแพร่ในเบราว์เซอร์เท่านั้น แยกจากฉบับร่าง ไม่ส่งขึ้นอินเทอร์เน็ต
- ข้อมูลเก็บเฉพาะเบราว์เซอร์และไฟล์/ที่อยู่ที่เปิด การล้างข้อมูลเบราว์เซอร์หรือเปลี่ยนที่อยู่ไฟล์อาจทำให้ไม่พบค่าที่บันทึกไว้
- ปุ่ม **เริ่มใหม่** คืนข้อมูลตัวอย่าง กดปุ่มย้อนกลับเพื่อย้อนการแก้ไขล่าสุดได้ในระหว่างเปิดหน้า

ไฟล์ต้นฉบับแยกอยู่ใน [prototype/](prototype/) โดยมี `index.html`, `styles.css`, `app.js` และรูปตัวอย่างใน `assets/` เปิด `prototype/index.html` ได้โดยตรงเช่นกัน

ลิงก์ Grab, LINE, Facebook และแผนที่เปิดช่องทางจริงของร้าน รูปอาหาร ราคา และภาพแผนที่ในต้นแบบเป็นตัวอย่าง การแชร์จากไฟล์ในเครื่องเป็นเพียงลิงก์ตัวอย่าง ยังไม่ใช่ URL สินค้าที่เผยแพร่สาธารณะ


### การปรับแต่งล่าสุด

- เปิดการ์ด Section แล้วแก้ไขในตัวการ์ดได้เลย
- ช่องทางติดต่อเพิ่ม/ลบ/เรียงปุ่ม แก้คำ ลิงก์ ไอคอน และสีปุ่มได้อิสระ
- Top bar เลือกโลโก้หรือชื่อ ฟอนต์เฉพาะชื่อ สีพื้น และสไตล์ปุ่มเมนูได้
- Sidebar สีเทากลาง ไม่ใช้เส้นเน้นซ้าย
- ฟอนต์ใช้ฟอนต์ที่มีในเครื่อง พร้อมฟอนต์สำรอง จึงเปิดต้นแบบได้แบบออฟไลน์

หลังแก้ไฟล์ต้นฉบับ สร้าง HTML รวมใหม่ได้ด้วย `python3 prototype/build.py`


### Social Platforms และปุ่ม DIY

แยกเป็น 2 Section โดย Social Platforms มีตัวเลือก Facebook, Instagram, TikTok, Google Maps, YouTube, LINE, Grab และ LINE MAN ใช้ไอคอนและสีประจำแพลตฟอร์มอัตโนมัติ แก้ข้อความ ลิงก์ และเลือกสีใหม่หรือคืนสีแบรนด์ได้

ปุ่ม DIY ตั้งข้อความ ลิงก์ ไอคอน และสีเองได้ เช่น ปุ่มที่จอดรถ ทั้งสอง Section เพิ่ม/ลบ/เรียงปุ่มและเปิด–ปิดได้

บนมือถือระบบพยายามเปิดแอปเมื่อรองรับ และใช้เว็บสำรอง ส่วนเดสก์ท็อปเปิดเว็บตามปกติ ยังต้องทดสอบการเปิดแอปกับ iPhone/Android จริงก่อนใช้ในระบบเผยแพร่ รายละเอียดวิธีเปิดและข้อจำกัดอยู่ใน HANDOFF.md


ตั้งจำนวนคอลัมน์ปุ่มได้ในการ์ดของแต่ละ Section: **1 คอลัมน์ / 2 คอลัมน์** ทุกปุ่มใช้ค่าเดียวกันทั้ง Section โดย Social และ DIY ตั้งแยกกันได้ ปุ่มสุดท้ายของแถว 2 คอลัมน์จะไม่ขยายเต็มแถวเมื่อจำนวนปุ่มเป็นเลขคี่

### Header และ Footer

Top bar ย้ายไปเมนูหลัก **Header** และติดด้านบนเวลาเลื่อน คงการตั้งค่าโลโก้ ชื่อ ฟอนต์ สี และสไตล์เมนูเดิม

เมนู **Footer** เปิด–ปิดแถบติดด้านล่างได้ เลือกระหว่างปุ่ม Social 1–2 คอลัมน์ (ฟังก์ชันเดียวกับ Section Social) หรือเมนูไอคอน DIY สูงสุด 5 ช่อง ไอคอนบน คำล่าง แก้ลิงก์ ข้อความ ไอคอน และจัดลำดับได้ ค่าเริ่มต้น Footer ปิดอยู่ ให้เปิดสวิตช์เพื่อทดลอง


## ระบบทดลองบน Cloudflare (pidlokhub.com)

ใช้โค้ดชุดเดียวกับต้นแบบใน `prototype/` แต่เก็บข้อมูลบนเซิร์ฟเวอร์ และให้หนึ่งบัญชีมีได้หลายแบรนด์

| URL | ใช้ทำอะไร |
|---|---|
| `pidlokhub.com/<slug>` | หน้าแบรนด์สาธารณะ (ฉบับเผยแพร่ล่าสุด) |
| `pidlokhub.com/admin` | รายการแบรนด์ของฉัน เพิ่ม/ลบแบรนด์ (ต้องล็อกอิน) |
| `pidlokhub.com/admin/<slug>` | CMS ของแบรนด์ บันทึกร่างอัตโนมัติ กดเผยแพร่เพื่อขึ้นหน้าจริง |

- **ล็อกอิน**: Cloudflare Access (รหัสทางอีเมล) ครอบ `/admin` และ `/api/admin` เพิ่ม/ลบผู้ทดลองที่ Zero Trust › Access › Applications › `pidlokhub admin` › Policies
- **โครงสร้าง**: Worker `pidlokhub` (`src/index.js`), D1 `pidlok-db` (ตาราง `brands`), R2 `pidlok-media` (รูปที่อัปโหลด เสิร์ฟที่ `/media/...`)
- Worker ตรวจ JWT ของ Access เอง (`src/auth.js`) และแก้ได้เฉพาะแบรนด์ที่ `owner_email` ตรงกับผู้ล็อกอิน
- ไฟล์หน้าเว็บใน `prototype/` ถูกฝังเข้า Worker ตอน build (`scripts/build-static.mjs`)

### พัฒนาและ deploy

```bash
npm install
```

```bash
echo 'DEV_USER_EMAIL=you@example.com' > .dev.vars
```

```bash
npm run db:migrate:local
```

```bash
npm run dev
```

เปิด `http://localhost:8787/admin` (ในเครื่องจะล็อกอินเป็น `DEV_USER_EMAIL` อัตโนมัติ ใช้ได้เฉพาะ localhost)

Deploy ขึ้น production โดยตรง (ไม่มี staging):

```bash
npm run db:migrate
```

```bash
npm run deploy
```

ใน cloud session ของ Claude ให้ตั้ง `CLOUDFLARE_API_TOKEN=proxy-injected` และ `CLOUDFLARE_ACCOUNT_ID` ก่อนรัน เพราะ proxy ใส่ token จริงให้
